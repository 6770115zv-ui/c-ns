# Technical writing

## תהליך
1. זהה קהל יעד ומה הוא צריך לבצע או להבין.
2. כתוב prerequisites מדויקים: OS, גרסאות, הרשאות, secrets ושירותים חיצוניים.
3. תן מסלול quick start עובד לפני הסבר ארוך.
4. השתמש בפקודות ובדוגמאות שנבדקו בפועל; ציין placeholders באופן ברור.
5. תעד configuration, failure modes, troubleshooting ו־security considerations.
6. סנכרן README עם התנהגות הקוד וה־workflow הנוכחיים.
7. בדוק קישורים ושמות קבצים מול הריפו.

## כללים
- אל תבטיח תמיכה שלא נבדקה.
- הבדל בין required, optional ו־recommended.
- כתוב קצר, עקבי וניתן לסריקה; הימנע מתיעוד כפול וסותר.
